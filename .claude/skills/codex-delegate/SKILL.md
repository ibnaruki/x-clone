# Codex に実働させる（窓口は Claude）

ユーザーと話すのは Claude だけ。Codex は裏で作業し、結果をファイルで返す。
Claude は結果を確認してから、平易な日本語で結論を先に報告する。Codex の出力をそのまま貼らない。

## どちらがやるか
| 作業 | 担当 |
|---|---|
| ブラウザ操作・サイト巡回・PC操作 | Codex |
| 画像生成、チラシ・バナーの写真やイラスト | Codex |
| 写真・航空写真・地図を見ての判定（庭の広さ、隣家との距離など） | Codex（重要な判定は Claude も確認） |
| AGENTS.md があり「Codex が正本」とされたフォルダでの作業 | Codex |
| 判断・要約・文章・通知、毎日動くプログラムの作成と修正 | Claude |
| チラシ・パンフレットの文章と構成 | Claude（ビジュアルは Codex） |

毎日決まったサイトを読むだけの巡回は、AIのブラウザ操作より Python のプログラムのほうが速くて安定する。
Codex には、初めて見るサイトの調べ方、手作業になっているサイト、写真や地図の判断を任せる。

## 呼び出し方
Bash で実行する。timeout は 600000 を指定する。長い作業はバックグラウンドで実行して完了を待つ。

```bash
OUT="$HOME/codex-jobs/$(date +%Y%m%d_%H%M%S)"; mkdir -p "$OUT"
cat > "$OUT/task.md" <<'EOF'
（作業の指示。下の「指示の書き方」に従う）
EOF
codex exec --skip-git-repo-check -C "作業フォルダ" -s workspace-write \
  -o "$OUT/result.md" - < "$OUT/task.md" > "$OUT/log.txt" 2>&1
cat "$OUT/result.md"
```

- 読むだけの作業は `-s read-only` にする
- 画像を渡すときは `-i 画像パス` を付ける
- 失敗したら `log.txt` を読んで原因をユーザーに伝える。成功したふりをしない

## 指示の書き方
Codex は会話の流れを知らないので、毎回これだけで分かるように書く。
1. 目的と背景（1〜3行）
2. 具体的な作業
3. 守ること
   - 作業フォルダに AGENTS.md・README.md があれば先に読んで従う
   - CAPTCHA やアクセス制限は突破しない。取れなかったら日時・URL・理由を書く
   - 購入・申込・問い合わせ送信・会員登録・ログインはしない。必要ならそこで止めて報告する
   - 指定以外のファイルを消したり上書きしたりしない
4. 出力の形
   - 結果は `$OUT`（または指定フォルダ）に保存する
   - 最後のメッセージに「やったこと／結果／取れなかったこと／次に人がやること」を書く

画像生成では、指示に「$imagegen を使って」と書き、保存先・サイズ・枚数を指定する。

## 報告の形
```
結論：…
Codex がやったこと：…
取れなかったこと・要確認：…
次にやること：…
```
画像を作ったときは保存先のパスを書く。

## 初回の動作確認
Codex で使える道具を確認してから使い始める。
```bash
codex exec --skip-git-repo-check -s read-only "使えるツール（ブラウザ操作、画像生成、PC操作）を一覧にして、それぞれ使えるか答えて。何も操作しないで。"
```
ブラウザ操作の道具が無ければ、Codex の設定ファイル（`~/.codex/config.toml`）への Playwright MCP の追加をユーザーに提案する。設定は勝手に変えない。
